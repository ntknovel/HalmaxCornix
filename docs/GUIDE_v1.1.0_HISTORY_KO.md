# CCK BALL 4×6 · MODU STENO · USB/BLE Studio v1.1.0

**빌드용 전체 소스 / 실제 ARM 빌드·실기 연결 미검증. UF2가 들어 있는 ZIP이 아닙니다.**

## 대상과 기준

CCK-BALL **4×6형**, nice!nano v2 호환 nRF52840, 양쪽 회전 인코더(클릭 없음), 오른쪽 PMW3610 트랙볼을 대상으로 합니다. 이전 `CCK-BALL-4x6-Keyball-Stable-GitHub-Upload-v1.0.zip`을 하드웨어 기준으로 삼고, `MODU-C STENO v0.3.1 / Compact71`의 한국어 속기 엔진과 상단 보조키 처리를 이식했습니다. **MODU의 기판·센서 핀·트랙볼 제어 드라이버를 복사한 펌웨어가 아닙니다.**

**이 키보드는 RIGHT가 central입니다. USB Studio는 오른쪽에 연결합니다.** CORNIX/KLOR/MODU 안내의 왼쪽 central 지시와 혼동하지 마세요. 왼쪽은 peripheral로 키·인코더 데이터를 보냅니다.

기존 원본의 논리 매트릭스 위치 **60개**에 회전 배정용 가상 위치 **4개**를 추가했습니다. 물리 키가 64개이거나 휠에 클릭 스위치가 생긴다는 뜻이 아닙니다.

## 빌드

기존 `GitHub ZMK 자동 빌더 v1.1.0`에서 이 전체 소스 ZIP을 선택합니다. 기존 전용 저장소 URL 또는 새 저장소 만들기와 GitHub 토큰을 입력하고 빌드를 시작합니다. ZIP은 풀어서 다른 소스에 합치지 않습니다.

산출 목표:

| 파일 | 기록할 위치 |
|---|---|
| `cck_ball_left_steno_v1_1_0.uf2` | 왼쪽 peripheral |
| `cck_ball_right_steno_studio_v1_1_0.uf2` | 오른쪽 central / 트랙볼 / Studio |
| `cck_ball_settings_reset_v1_1_0.uf2` | 필요할 때만 사용하는 설정 초기화 |

이름은 실제 생성 확인이 아니라 **빌드 목표**입니다. Actions의 소스 검사와 세 펌웨어 타깃이 모두 성공한 실행에서만 UF2를 받습니다. 평소에는 left/right를 해당 유닛에 각각 기록하고, settings_reset부터 넣지 않습니다. 이전 정상 UF2와 개인 설정을 먼저 보관하세요.

자동 빌더 외에 저장소에서 실행할 때:

```sh
bash tests/run.sh
# GitHub Actions: CCK Ball 4x6 STENO Dual Studio v1.1.0
```

이전 CCK 원본이 참조하던 `imhy123/zmk: v0.3-branch`, `DoctorWangWang/zmk-pmw3610-driver: main`을 유지했습니다. **두 의존성이 불변 commit SHA로 고정됐다는 뜻은 아닙니다.** 실제 빌드가 해결한 커밋을 로그에서 확인해야 합니다. 현재 제작 환경은 west/ARM SDK가 없고 GitHub 파일 다운로드에 DNS 오류가 발생하여 의존성 전체 컴파일을 하지 못했습니다.

## 일반 키와 속기 진입

기본 문자·숫자행은 CCK 원본 배정입니다. 핵심 변경:

| 위치(0부터) | 배정 |
|---:|---|
| 11 | 맨 위 오른쪽 Backspace, 유지 |
| **23** | **Backspace 바로 아래, 오른쪽 바깥 키: BASE ↔ STENO** |
| FN 23 | 원래 이 위치의 역슬래시 `\` |
| FN 13 | 누르는 동안 SNIPE(정밀 트랙볼) |
| FN 14 | 누르는 동안 Symbols |
| BT 06 / 07 | USB 출력 / BLE 출력 |
| BT 08 / 09 | 오른쪽 central 부트로더 / 재시작 |

기존 BASE의 53번을 누르면 Fn, 54번을 누르면 Bluetooth 레이어입니다. **속기에서는 같은 엄지들이 모음이 되므로 먼저 23번으로 일반 모드에 나와 설정 레이어를 사용합니다.**

속기 전환은 모드키를 뗄 때 확정됩니다. 기본 진입만으로 OS의 현재 한/영 상태를 알아서 판단하지는 않습니다. 한국어 음절 출력에는 호스트의 한국어 두벌식 입력 상태가 필요합니다.

## 양쪽 휠: 클릭 없음 / 네 칸으로 편집

모든 레이어의 초기 회전 배정은 다음과 같습니다.

| 가상 위치 | 입력 | 초기 출력 |
|---:|---|---|
| 60 | 왼쪽 시계 방향 | ↑ |
| 61 | 왼쪽 반시계 방향 | ↓ |
| 62 | 오른쪽 시계 방향 | ← |
| 63 | 오른쪽 반시계 방향 | → |

Studio/DYA에서 **배열 맨 아래의 추가 네 칸**을 일반 키처럼 골라 배정을 바꿉니다. 이 칸은 실제 클릭 버튼이 아니라 휠 회전의 출력 설정입니다. 레이어마다 다른 배정이 가능합니다. 실제 회전 방향이 기판 배선 기준과 반대라면 해당 휠의 두 칸을 서로 교환해 저장합니다.

표준 센서 회전 처리는 그대로 사용하고, 출력할 때 현재 Studio 키맵의 해당 칸을 조회합니다. 누름과 해제 사이에 레이어/배정이 달라져도 **누를 때 기억한 동작을 해제**합니다. 속기 역할 이벤트로 가짜 물리키를 올리지 않으며, 휠을 클릭으로 처리하지 않습니다.

회전 한 단계는 10ms 누름·해제 펄스입니다. 홀드탭을 배정해도 실제로 눌러 유지할 수 있는 버튼이 되지 않습니다. 방향·단축키·미디어·마우스처럼 펄스에 적합한 동작을 배정하세요. `CCK Internal wheel routing`은 내부 전용이므로 배정하지 마세요. STENO의 기본 휠은 같은 방향키를 속기 출력 큐로 보내며 60~63을 자모 역할로 바꾸는 것은 지원 범위 밖입니다.

## 속기 배열과 규칙

| 행 | 왼손 | 오른손 |
|---|---|---|
| 자음 위 | ㅂ ㅈ ㄷ ㄱ ㅅ | ㅅ ㄱ ㄷ ㅈ ㅂ |
| 자음 가운데 | ㅁ ㄴ ㅇ ㄹ ㅎ | ㅎ ㄹ ㅇ ㄴ ㅁ |
| 자음 아래 | ㅋ ㅌ ㅊ ㅍ 쌍초 | 쌍종 ㅍ ㅊ ㅌ ㅋ |
| 엄지 모음 | ㅗ ㅡ ㅜ | ㅓ ㅣ ㅏ |

숫자행은 MODU의 보조키 처리입니다. 속기 중 상단 숫자를 누를 수 있고, 기호L/R을 더하면 해당 기호, 겹모L/R을 더하면 기능키로 해석합니다. 숫자를 누른 뒤 선택자를 먼저 떼어도 해제할 키가 바뀌지 않습니다. 위쪽 Tab 보조키도 유지합니다.

원본 MODU/Cornix 논리 사전 43개, Quick 문구 12개, 11개 합법 겹받침, 미러 종성→초성 입력(ㅗ/ㅡ/ㅜ), 전용 쌍초/쌍종 교차 규칙을 유지했습니다. 예: `종ㅂ+ㅜ=부`, `쌍초+종ㅂ+ㅜ=뿌`, `쌍종+초ㅂ+ㅏ=빠`.

단독 자모 수정은 기존 500ms 정책입니다. 일반 조합은 마지막 역할키 해제 시 확정하며, 전역 key-up 삭제 보정은 0ms(비활성화)입니다. 90ms는 합법 겹받침의 국소 판정이지 매 음절을 90ms 지연시키는 설정이 아닙니다.

**속기 58번**은 단독으로 500ms 미만에 떼면 순수 RAlt, 500ms 홀드 또는 다른 키와 누르면 SELECT SHIFT입니다. SELECT SHIFT는 오른손 I/J/K/L 위치(20/31/32/33)를 선택 방향키로 사용합니다. 선택 뒤 떼면 RAlt를 추가로 보내지 않습니다. 이 홀드탭은 표준 ZMK 선언을 적용했으며 실제 기기의 첫 방향키/해제 순서 검증은 남아 있습니다.

이 CCK 배정은 **MODU 속기 기준**입니다. 후속 CORNIX v2.2.8의 단독 기호 수정 네 가지나 Halmax 비속기 키맵을 자동으로 합치지 않았습니다. 단독 출력/약어 원문은 `modules/cck-steno/config/`와 decoder에 있습니다.

## 트랙볼

오른쪽 PMW3610의 원본 설정을 유지했습니다: CPI 400, snipe CPI 200, scroll tick 70, orientation 270, X 반전, 125Hz 소프트웨어 폴링 및 smart algorithm. 입력 센서 SPI0의 SCK P0.08, SDIO P0.17, CS P0.20, IRQ P0.06과 매트릭스·인코더 핀은 바꾸지 않았습니다.

기존 F(28번) 홀드 → Scroll 레이어 3, 새 Fn+Q(13번) 홀드 → Snipe 레이어 4입니다. 속기에서도 트랙볼 포인터 처리는 유지하도록 구성했습니다. **MODU의 별도 실시간 CPI API, 트랙볼을 네 방향 키로 바꾸는 자체 모듈, DYA 전용 트랙볼 설정창까지 복제한 버전은 아닙니다.**

기존 두 overlay의 사용하지 않는 RGB SPI3가 매트릭스 P0.10과 겹쳐, SPI3를 비활성화했습니다. 센서 SPI0는 유지합니다. 이번 빌드는 RGB/속기 LED를 제공하지 않습니다. 기존 의존성의 오래된 중앙역할 Kconfig 이름도 실제 ZMK의 `ZMK_SPLIT_ROLE_CENTRAL`로 바로잡았습니다.

## Studio / DYA 연결과 범위

- PC 공식 ZMK Studio: **오른쪽 데이터 USB** → USB 장치 선택. 별도의 Unlock 키 없음.
- DYA Studio: 표준 Studio 프로토콜로 USB 또는 BLE 키 배정/네 가상 휠 배정 편집을 지원하도록 구성.
- Android: Chrome의 DYA Studio BLE. iOS: DYA가 안내하는 Bluefy BLE. 이 조합은 개발자 지원표 기준이며 이 CCK 기기의 실기 인증이 아닙니다.
- BLE 편집 시에는 PC 데이터 USB를 분리하고, 휴대폰용 활성 Bluetooth 프로필을 선택/페어링합니다. BT 레이어 07번의 OUT_BLE를 명시적으로 선택할 수도 있습니다.
- USB를 연결하면 오른쪽이 USB 출력을 한 번 자동 선택합니다. 수동 OUT_BLE 선택은 다음 재연결까지 존중합니다.
- Bluetooth 페어링·브라우저 장치 권한은 여전히 필요합니다. 잠금이 없으므로 신뢰하는 호스트만 사용합니다. 두 편집기를 동시에 열어 저장하지 마세요.

**DYA 런타임 매크로·콤보 확장, 속기 사전/시간의 앱 실시간 저장은 넣지 않았습니다.** NTK 앱 0.2.2의 고급 로컬 초안도 이 펌웨어에 자동 적용되지 않습니다. 이 ZIP은 그 미완성 확장을 완성했다고 주장하지 않습니다. 해당 정의 변경은 소스 변경과 재빌드 대상입니다.

Studio에서 일반 키와 휠 배정을 바꿀 수 있으나 STENO 5, SELECT 6, 센서 Scroll 3/Snipe 4의 번호/순서와 속기 역할 위치는 유지하세요. 임의 속기 재배열은 엔진 위치참조를 함께 수정하는 작업입니다. 화면에서 수정 금지 영역을 완전히 숨기는 기능은 구현하지 않았습니다.

원래 CCK Studio 키맵이 저장돼 있으면 새 기본값보다 우선할 수 있습니다. 기존 값을 백업한 뒤 **Restore Stock Settings**로 이번 64칸 기본값을 읽어야 할 수 있습니다. 이는 개인 키맵을 버리는 동작이며, 페어링까지 지우는 settings_reset을 먼저 쓰라는 뜻은 아닙니다.

## 실제 수행한 검사 / 남은 것

`tests/run.sh`는 원본 GPIO/센서/60좌표 보존, 8×64 배정, 23번 모드키, 42개 역할·변환, 실제 C 속기 엔진 회귀, C 휠 라우터(레이어 변경·양손 방향 분리·해제 보존·오류), USB 자동 선택을 검사합니다. 실제 CMake를 가짜 ZMK 헤더와 구성해 알려진 두 API 형식과 주변장치 제외·오류 차단을 확인합니다. 메타데이터를 켠 C 소스 형식 검사도 별도로 실행합니다.

GCC/Clang·ASan/UBSan 호스트 시험은 실제로 실행했습니다. 다만 **west/Zephyr devicetree/Kconfig/ARM 최종 링크·UF2 생성, 센서/무선/USB Studio 저장·재접속·전원 재투입은 미실행**입니다. donor 로그의 이름이 Cornix/MODU로 나오는 것은 원본 논리 회귀시험을 유지한 것이며 그 로그를 CCK 하드웨어 시험으로 읽으면 안 됩니다. `verification/EXECUTED_HOST_TESTS.txt`에서 이번 실행을 확인하세요.

첫 실기: 일반 전체 키 → 양쪽 휠 → 오른쪽 트랙볼 → 23번 속기 전환 → 부/뿌/빠·약어 → 숫자행 → 58번 RAlt/선택 → USB 키/휠 한 개 변경·저장·재접속 → BLE 편집 순서입니다.
