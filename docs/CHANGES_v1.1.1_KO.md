# CCK Ball 4×6 v1.1.1 — 속기 Tab/기호 · ㅏ 방향키 · ㅓ 마우스/트랙볼 스크롤

**CCK 4×6 v1.1.0에서 수정한 전체 빌드 소스입니다. UF2 없음. 실제 ARM 빌드·키보드 타건·Studio 연결은 미검증입니다.**

오른쪽 = central / PMW3610 / USB Studio, 왼쪽 = peripheral. MODU 기판의 GPIO를 이식하지 않았습니다.
이번 동작 변경의 대상은 **STENO 레이어 5**입니다. 사용자 문맥의 `tap`은 **Tab 키**로 해석했습니다.
위쪽에 `~`가 있던 표는 속기 배열이므로 BASE의 Esc·Tab·Backspace는 변경하지 않았습니다.
`ㅏ`의 별도 출력이 지정되지 않아 **기존 ㅣ와 동일한 방향키 조합**으로 구현했습니다.

## 1. 속기 Tab과 위쪽 기호

| 물리 위치 | 이전 속기 배정 | 이번 속기 배정 |
|---:|---|---|
| 00 | ~ | **!** |
| 11 | Backspace | **?** |
| 12 | Tab | **단독 200ms 미만에 떼면 ~ / 200ms 이상 홀드하면 Tab** |
| 59 | Backspace | 그대로 |

12번은 누르는 즉시 `~`를 찍었다가 지우는 방식이 아닙니다. 짧은 탭의 해제에서만 `~`를 보냅니다.
Ctrl(좌/우), Alt(좌/우), LGUI가 이미 눌려 있으면 12번은 `~` 대신 Tab이며 해당 수정키를 유지합니다.
수정키를 먼저 누르는 순서가 기준입니다. 12번을 먼저 누른 뒤 수정키를 더하는 반대 순서까지 같은 결과라고 보장하지 않습니다.
200ms와 수정키 선택은 표준 ZMK hold-tap/mod-morph 설정입니다. 실제 ZMK의 이벤트/hold-tap 큐는 이 제작 환경에서 실행하지 않았습니다.

기존 MODU 상단 선택자 기능도 보존했습니다. 아래 표는 다른 설정 레이어가 위에 올라와 있지 않은 속기 상태의 역할 선택자입니다.

| 위치 | 선택자 없음 | 기호L/R 선택자 | 겹모L/R 선택자 |
|---:|---|---|---|
| 00 | ! | 백틱 ` | Esc |
| 11 | ? | Backspace | F11 |
| 12 | 탭 ~ / 홀드 Tab | Tab | F12 |

BASE 00=Esc, BASE 11=Backspace, BASE 12=Tab은 v1.1.0 그대로입니다.
23번 속기 전환키, 58번 단독 RAlt/SELECT SHIFT, 모든 휠 배정도 그대로입니다.

## 2. ㅣ와 ㅏ: 방향키

**먼저 ㅣ(55) 또는 ㅏ(56)만 누른 뒤** 아래 물리 키를 누릅니다.

| 물리 키 / 위치 | ㅣ를 누른 상태 | ㅏ를 누른 상태 |
|---|---|---|
| J / 31 | ← | ← |
| L / 33 | → | → |
| I / 20 | ↑ | ↑ |
| K / 32 | ↓ | ↓ |

문자 I/J/K/L는 기본 모드의 위치 이름입니다. 속기 모드에서는 종성 역할이지만, 모음을 먼저 단독으로 잡은 이 동작에서만 방향키가 됩니다.
방향키가 눌린 상태에서 해당 키를 놓으면 방향키를 해제하고, 모음을 먼저 놓으면 아직 눌린 방향키를 모두 해제합니다.
방향 조작을 끝내며 모음을 놓아도 ㅣ/ㅏ를 추가 출력하지 않습니다. 일반 음절에 이미 참여한 모음은 이 단독 앵커로 탈취하지 않습니다.

## 3. ㅓ: 마우스 키와 트랙볼 스크롤

**먼저 ㅓ(54)만 누른 뒤** 마우스 키를 누르거나 트랙볼을 움직입니다. 500ms를 기다릴 필요는 없습니다.

| 입력 | 결과 |
|---|---|
| ㅓ + J(31) | 왼쪽 마우스 버튼 |
| ㅓ + L(33) | 오른쪽 마우스 버튼 |
| ㅓ + I(20) | 위로 스크롤 |
| ㅓ + K(32) | 아래로 스크롤 |
| ㅓ + 쉼표 `,` / `<` 자리(44) | 가운데 마우스 버튼 |
| ㅓ + 트랙볼 | 포인터 움직임 대신 스크롤 |

마우스 버튼은 해당 키를 누르는 동안 유지되고 키를 놓으면 해제합니다. I/K는 기존 ZMK 마우스 스크롤 동작을 사용하며 누르고 있는 동안 반복됩니다.
ㅓ를 먼저 놓거나 속기를 종료/취소하면 아직 눌려 있는 마우스 출력도 정리합니다. J/L/쉼표 버튼은 서로 구분합니다.

트랙볼은 기존 오른쪽 센서의 X/Y 이벤트를 스크롤 이벤트로 바꿉니다. 세로·가로 스크롤을 지원하고 기존 `PMW3610_SCROLL_TICK=70`을 변환 기준으로 사용합니다.
CPI 400, Snipe CPI 200, 270도 방향·X 반전, 125Hz 및 SPI/GPIO는 변경하지 않았습니다. 기존 F 홀드 Scroll와 Fn+Q Snipe도 유지합니다.
센서 드라이버 자체나 레이어 번호를 바꾸지 않았습니다. SCROLL 레이어 3을 STENO 5 아래에 켜는 것만으로는 원본 드라이버의 최상위 레이어 판정에 잡히지 않으므로, STENO 전용 input processor를 오른쪽 센서 리스너에 연결했습니다.
동시에 보고되는 X/Y 한 묶음은 같은 모드로 처리하여, 중간에 ㅓ를 놓아도 하나의 센서 프레임이 포인터와 스크롤로 갈라지지 않게 했습니다.

### Space와 모음의 불필요한 출력 방지

- ㅓ만 500ms 미만 누르고 떼고, 마우스/트랙볼을 사용하지 않음 → 기존 Space.
- ㅓ만 500ms 이상 누르고 떼고, 마우스/트랙볼을 사용하지 않음 → 기존 직접 ㅓ.
- ㅓ + 마우스 키 또는 실제 0이 아닌 트랙볼 움직임 → 보조 동작에 사용한 것으로 처리. 해제 시 **Space나 ㅓ 추가 출력 없음**.
- 센서의 0/0 보고만 온 경우 → 보조 동작으로 소비하지 않음.
- 이미 자음·다른 모음이 참여한 속기 조합 → 일반 속기 해석 유지. 트랙볼은 기존 포인터 경로 유지.

아주 작은 0이 아닌 센서 움직임도 보조 동작을 사용한 것으로 간주합니다. 아직 스크롤 1칸에 못 미친 움직임이라도 해제 시 Space를 출력하지 않습니다.
따라서 모음 입력 중에 의도치 않게 트랙볼을 건드리는 경우까지 자동으로 구분하는 기능은 아닙니다. 물리 키·센서 사용 의도까지 알아내는 판정이라고 표현하지 않습니다.
보조 모드가 시작된 뒤에는 일반 자모를 같은 스트로크에 혼합하지 않습니다. 모음을 놓고 다음 속기 입력을 시작합니다.

## 4. 보존과 편집 범위

- 기존 약어 43개·Quick 12개, 디코더와 사전 데이터 보존.
- 종성→초성 ㅗ/ㅡ/ㅜ 피로분산, 전용 쌍초/쌍종 교차 규칙 보존.
- 500ms 단독 자모·빠른 일반 chord·11개 합법 겹받침 판정 유지.
- 23번 일반↔속기 전환, 58번 짧은 RAlt/홀드 SELECT SHIFT, 휠 가상 슬롯60~63 보존.
- USB/BLE Studio, 상시 잠금 해제, 오른쪽 USB 자동 선택, BLE split 유지.
- DYA/공식 Studio의 표준 키 배정 호환 목표 유지. **런타임 매크로·콤보/속기 사전의 동적 저장은 이번에 추가하지 않았습니다.**
- 원본 `imhy123/zmk v0.3-branch`, PMW3610 driver `main` 의존성을 그대로 사용합니다. 불변 커밋 고정으로 표현하지 않습니다.

ㅣ/ㅏ/ㅓ와 JLKI·쉼표의 보조 조합은 속기 엔진 내부 규칙입니다. Studio에서 역할을 임의 위치로 옮기면 이 위치 의존 규칙도 함께 수정해야 합니다.
STENO5, SELECT6, SCROLL3, SNIPE4의 번호/순서를 유지하세요. 다른 유닛의 핀/배열로 치환한 펌웨어가 아닙니다.

## 5. 빌드·설치

기존 GitHub ZMK 자동 빌더에서 **이 v1.1.1 전체 소스 ZIP**을 선택해 새 빌드를 시작합니다.
과거 실패 실행에서 Re-run만 하면 그 실행의 이전 소스를 다시 빌드할 수 있으므로 새 소스 업로드를 구분하세요.

```text
cck_ball_left_steno_v1_1_1.uf2          → 왼쪽
cck_ball_right_steno_studio_v1_1_1.uf2 → 오른쪽
cck_ball_settings_reset_v1_1_1.uf2     → 필요할 때만 쓰는 초기화
```

이는 **산출 목표**이지 이미 생성된 UF2 목록이 아닙니다. Actions의 소스 검사와 세 타깃이 성공한 결과만 사용합니다.
오른쪽이 central이며 Studio USB도 오른쪽입니다. left/right UF2를 서로 바꾸지 마세요.

Studio에 v1.1.0의 Tab 배정을 저장했다면 그 저장값이 새 `~ / Tab` 기본값보다 우선할 수 있습니다.
개인 설정을 백업한 후 새 기본값을 쓸 때는 **Restore Stock Settings**가 필요할 수 있습니다. 전체 설정/페어링 초기화 UF2부터 넣지 마세요.
이번 소스가 Studio 설정이나 페어링을 자동으로 지우지는 않습니다.

## 6. 검증 범위

`bash tests/run.sh`는 실제 수정 C 엔진·dual 상태·마우스 동작 디스패처·트랙볼 input processor를 호스트 대역 환경에서 실행합니다.
2079개 보조 입력 사례(선행 모음/해제 순서/다섯 마우스 출력/스크롤 잔여/0 움직임/일반 음절 보존/임의 시퀀스)를 GCC와 Clang ASan/UBSan에서 검사합니다.
새 옵션을 켠 상태에서 원래 엔진/전체 회귀도 다시 실행합니다. 기존 속기·좌표 변환·MODU 상단 보조키·휠·USB 시험도 실행합니다.
Tab 200ms/modifier 분기는 실제 설정 검사와 **명세 모델**로 검사하며 ZMK 원본 hold-tap 큐를 실행한 시험이 아닙니다.
CMake 검사는 실제 CMake를 사용하지만 ZMK API 헤더는 모의 헤더입니다. Devicetree/Zephyr 전체 빌드나 센서/무선 실기 시험이 아닙니다.

**이 환경에서 ARM 최종 컴파일, UF2 생성, 센서·BLE·USB·DYA/ZMK Studio 저장, 키보드 실물 타건은 실행하지 않았습니다.**
후속 실기 순서: 새 배열 적용 → ~ / Tab / ! / ? → ㅣ/ㅏ 네 방향 → ㅓ 클릭/휠/중앙버튼 → ㅓ+볼 → Space 및 일반 음절 → 모드/선택 해제 후 잔류 입력 확인.
